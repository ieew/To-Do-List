# Android core-domain 与数据层规格

> 本文件是 Android 端 `core/domain` 与 `core/data` 的唯一权威。与 `conventions.md` 冲突时以 `conventions.md` 为准。
> 不描述 UI 与 HTTP；同步见 `android-sync-integration.md`，界面见 `android-ui-spec.md`。

## 一、硬约束（CI 强制）

| 编号 | 约束 | 检查方式 |
|---|---|---|
| C1 | `core/domain` 不得 import `android.*`、`androidx.*`、`retrofit2.*`、`okhttp3.*` | Gradle 模块类型为 `java-library`；Konsist 断言无禁止 import |
| C2 | `core/domain` 不得读取物理时钟：禁止 `System.currentTimeMillis()`、`System.nanoTime()`、`java.time.*`、`kotlinx.datetime.Clock` | CI 静态扫描 |
| C3 | `core/domain` 只接受和返回纯数据结构；错误用 `sealed class DomainError` | 代码评审 + 单测 |
| C4 | `feature/*` 不得直接 import `core/data/dao/*` 或 `core/network/api/*` | Konsist 规则 |
| C5 | 所有业务写操作必须经 `OpRepository.appendOps(...)`，同一 Room 事务内完成 | 单测断言事务 |
| C6 | `op_id` 全局唯一；重复 `appendOps` 必须幂等 | 单测 |

## 三、领域类型（必须字段齐全，命名一致）

### Hlc

- 字段：`physicalMs: Long`、`counter: Long`、`nodeId: String`
- 全序：`(physicalMs, counter, nodeId)`；比较 Op 时追加 `opId`
- `next(local, nowMs, nodeId)`：`nowMs > local.physicalMs` 时 `(nowMs, 0, nodeId)`，否则 `(local.physicalMs, local.counter+1, nodeId)`
- `observe(local, remote)`：只前进不回退；公式必须与 Windows `core_domain.rs` 完全一致
- **禁止**用 `toString()`、`hashCode()` 做排序

### Op

- 字段：`opId`、`workspaceId`、`entityType`、`entityId`、`actorId`、`deviceId`、`operation`、`field`、`value`、`hlc`、`source`、`model`
- `entityType ∈ {WORKSPACE, LIST, TAG, TASK, MEMBERSHIP, USER}`
- `operation ∈ {SET, ADD, REMOVE}`
- `source ∈ {HUMAN, AI, IMPORT, SYSTEM}`
- 领域类型 camelCase；wire（snake_case + 嵌套 hlc + source_meta）只在 `core/sync/wire` 转换

### State 与合并规则

- 字段单元格：`set` 按四元组 `(physicalMs, counter, nodeId, opId)` 取最大者（LWW）
- 集合元素（`__tag`、`__subtask`）：`add` / `remove` 各自记录最大四元组，`add >= remove` 时存活（add-wins）
- 子任务字段：`__subtask:<subtaskId>:text|done|order` 走 LWW
- `applyAll(ops)` 必须先按四元组排序再逐条 apply；收敛性由排序保证
- **禁止**为任何字段新增第三种合并方式（取最小值、取并集等）

### Projection

字段与 `server-protocol.md` 9.3 完全一致：`lists[]`、`tags[]`、`members[]`、`tasks[]`。
`tasks[].tagIds` 直接输出 OR-Set 存活元素，**不按** `tag.__deleted` 过滤（UI 结合 `tags` 列表隐藏）。
`Projection.build` 是确定性纯函数：任意 op 顺序 → 相同投影。

### Timeline

`buildTimeline(ops, workspaceId, taskId?, beforeSeq?, limit, nowMs)`：`nowMs` 由调用方传入。排序：`atMs` 降序，同毫秒按 `opId` 降序。`undone` 判定：存在更高四元组的 `task.__undo_of = opId`。

## 四、Room Schema（必须字段齐全）

### `op_log`

主键 `rowId` 自增；唯一索引 `op_id`；索引 `(sync_state, created_at)`、`(workspace_id, server_seq)`、`(entity_type, entity_id, physical_ms, counter, node_id, op_id)`。

字段：`op_id`、`workspace_id`、`entity_type`、`entity_id`、`actor_id`、`device_id`、`operation`、`field`、`value_json`、`physical_ms`、`counter`、`node_id`、`source`、`model`、`created_at`、`sync_state`、`server_seq`、`sync_error`。

- `sync_state ∈ {pending, synced, rejected}`
- `load_ops`（参与投影）过滤 `rejected`；`load_all_ops`（导出/排查）包含全部
- **禁止**另建 `pending_ops` 表；pending 即 `sync_state='pending'`
- **禁止**物理删除 `op_log` 行；删除实体写 `__deleted=true` 墓碑 op

### 其它表

| 表 | 主键 | 用途 |
|---|---|---|
| `meta` | `key` | `sync_cursor`、`sync_account`、`local_hlc`、`device_id` |
| `preferences` | `key` | `active_workspace_id`、`theme` |
| `local_prefs` | `key` | 便利贴布局、`current_user_id` |
| `task_local` | `task_id` | `last_fired_at`、`snooze_until`（提醒本地态） |

### 迁移

- Room `version` 从 1 开始；每次 schema 变更必须写 `Migration` 并附迁移测试
- `exportSchema = true`，schema JSON 入版本库，CI 校验无 diff

## 五、OpRepository 事务语义

`OpRepository` 是 `core/data` 唯一写入口，接口至少包含：

- `appendOp(workspaceId, build: (Hlc) -> Op): Op`
- `appendOps(workspaceId, build: (Hlc) -> List<Op>): List<Op>`
- `observeProjection(workspaceId): Flow<WorkspaceProjection>`
- `loadAllOps()` / `loadPendingOps(limit)` / `markSynced` / `markRejected` / `observeHlc(remote)`
- `importOps(ops): ImportResult`（走 appendOps，source=import，重复 op_id 跳过）

`appendOps` 的原子性（最容易被写错）：

1. 开启 Room `@Transaction`
2. 读 `meta.local_hlc`
3. 调用方基于当前 HLC 构建 op；如需多条，调用方负责逐条推进（`HlcClock.next`）
4. 逐条写 `op_log`，`sync_state='pending'`，`server_seq=null`
5. 写回 `meta.local_hlc`
6. 提交事务
7. **事务外**：`SyncNotifier.requestSync()` + `ProjectionCache.invalidate(workspaceId)`

**禁止**：
- 事务内调用网络或同步
- 事务内 emit StateFlow
- UI 层自己推进 HLC 或生成 op_id 后绕过 appendOps
- 「先写业务表再写 op_log」两步走：**没有业务表，只有 op_log**

- 测试断言 `State.applyAll(ops).projection(workspaceId)` 与 `expect.projection` 一致
- 必须覆盖：`lww.json`、`orset_add_wins.json`、`subtask_fields.json`、`tag_association.json`、`restore.json`

|---|---|

## 七、常见 bug 对照表

| # | 错误写法 | 正确做法 | 后果 |
|---|---|---|---|
| 1 | 用 `updatedAt` 或 `rowId` 做 LWW | 只用四元组 | 三端分叉 |

### Retrofit 接口

## 四、令牌

- access/refresh token 存 **Keystore 加密后的 DataStore**，禁止进 SQLite、日志、备份
- 请求前 60 秒主动刷新；`401 token_expired` 时刷新一次并重放
- refresh token 每次刷新都会轮换，**必须保存新值**
- 刷新必须**单飞**：`Mutex` 包住刷新逻辑，多并发共享同一次刷新结果
- `invalid_refresh_token` → 清除登录态，状态转 `auth_required`，UI 提示重新登录

**禁止**：token 进明文 SharedPreferences、`Log.d`、Crashlytics 自定义键。

## 五、同步一轮（`runOnce`）

`Mutex` 保证同时只有一轮；顺序：**先 push 后 pull**。

### push

1. 取 `loadPendingOps(100)`，按 `createdAt, rowId` 排序
2. `POST /v1/sync/push`，顶层 `device_id` + `ops`
3. `accepted` / `duplicate` → `markSynced(opIds, serverSeq)`
4. `rejected` → `markRejected(opId, "code: message")`，**不自动重试**；`workspace_access_revoked` / `forbidden` 红条；`hlc_too_far_ahead` 黄条 + `observeHlc`
5. 401 → 刷新 token 后重试一次；刷新失败 → `auth_required`
6. 413 → 批次减半重试；单条仍 413 → rejected
7. 整批 400/403 → 整批 rejected
8. 网络错误 / 5xx → 保留 pending，状态 `retrying`，指数退避

### pull

1. `GET /v1/sync/pull?since_seq=<cursor>&limit=200`，**不带** `workspace_id`（拉全部工作区）
2. 每页在**单个 Room 事务**内落库并推进 `meta.sync_cursor = next_seq`
3. `server_hlc` 调 `observeHlc`（只前进）
4. `has_more=true` 继续，单轮最多 20 页
5. 拉取落库后修正 `active_workspace_id`：不存在则回落到投影中第一个工作区

**禁止**：先 pull 后 push；pull 中途崩溃后 `sync_cursor` 超过已应用页；在 pull 事务内做网络请求。

## 六、触发与调度

| 触发源 | 实现 |
|---|---|
| 本地写入后 | `SyncNotifier.requestSync()`：前台 `SharedFlow.tryEmit`；后台 `OneTimeWorkRequest` + `ExistingWorkPolicy.REPLACE` |
| 前台常驻 | `SharedFlow` 在 `MainActivity` 生命周期内收集，直接 `runOnce()` |
| 周期兜底 | `PeriodicWorkRequest(15min)`，`Constraints: NetworkType.CONNECTED` |
| 下拉刷新 | 直接 `runOnce()` |
| 登录成功 | 立即 `runOnce()` 全量 pull |

退避：网络错误 / 5xx 用 `1s → 2s → 4s → … → 60s`，由 `SyncWorker` 的 `BackoffPolicy.EXPONENTIAL` 或 `SyncEngine` 内部维护。

`SyncWorker` 用 `CoroutineWorker`；不强制 `setForeground`（避免常驻通知），但长时间同步（>10min）需降级分页 pull。

**禁止**：用 `PeriodicWorkRequest` 作为唯一触发；`Worker` 内 `runBlocking` 整个同步。

## 八、账户生命周期

### 登录 / 注册

1. 调 `/v1/auth/login` 或 `/v1/auth/register`
2. 若本地 `sync_account` 与目标账户不同：
   - Room 备份到 `filesDir/backups/todo-<timestamp>.db`
   - 清空 `op_log` 与 `sync_*` meta
   - 重置 `local_hlc` 物理时间与计数器，保留 `node_id`
3. 同账户再次登录不清库
4. 写 `current_user_id`、`active_workspace_id`、`sync_account`，保存令牌
5. 状态置 `Offline` 后立即 `runOnce()` 全量 pull

### 登出

- 调 `/v1/auth/logout`（失败忽略），清 Keystore 令牌
- 保留本地数据与 `sync_account`，状态 `SignedOut`

## 九、错误映射

| 服务端 code | HTTP | 客户端处理 | UI |
|---|---|---|---|
| `workspace_access_revoked` / `forbidden` | 200/403 | 标记 rejected，不重试 | 红条「权限已变更，此操作未生效」 |

| 网络错误 / 5xx | — | 保留 pending，`retrying` | 标题栏「重试中」 |

| # | 错误写法 | 正确做法 | 后果 |

| 3 | 并发刷新 token 不单飞 | `Mutex` 包刷新 | refresh 家族被吊销 |

| 5 | 把 `message` 当判断依据 | 只按 `code` 分支 | 文案改动导致逻辑失效 |

| 7 | 在 Worker 里 `runBlocking` 整个同步 | `suspend` 直接调用 | ANR |
| 8 | token 存明文 SharedPreferences | Keystore + DataStore | 安全合规失败 |
| 9 | pull 带 `workspace_id` 却只拉一个 | 不带，拉全部 | 漏拉其他工作区 |
| 10 | `server_hlc` 不推进本地 HLC | `observeHlc` | 下一批 op 被拒 |

  1. 创建 `NotificationChannel`（提醒、同步）
  2. `bootstrap()`：读投影 + 同步状态，上限 3 秒
  3. 失败进入可重试错误页（`UiError.Bootstrap`），不渲染演示数据
- 首屏骨架：任务列表 3 条、进度卡 1 块，颜色 `border-2` 到 `border` 脉冲，1.2 秒
- **禁止**：先渲染种子数据再被真实投影覆盖；全屏 spinner

## 五、Hilt 模块（必须）

- `AppModule`：提供 `Room`、`OpRepository`、`SyncEngine`、`SyncNotifier`、`ProjectionHolder`、`SecureTokenStore`
- `NetworkModule`：提供 Retrofit、OkHttp、`TokenAuthenticator`、`AuthApi`、`SyncApi`
- `AiModule`：提供 `AiClient`、`AiKeyStore`
- `ReminderModule`：提供 `AlarmScheduler`
- Worker 用 `@HiltWorker` + `HiltWorkerFactory`；`Application` 实现 `Configuration.Provider`

## 六、`SyncNotifier` 契约（关键）

```kotlin
interface SyncNotifier {
    /** 前台共享流；MainActivity 生命周期内收集，直接触发 runOnce */
    val foregroundRequests: SharedFlow<Unit>
    /** 请求同步：前台发流；后台排 OneTimeWork(REPLACE) */
    fun requestSync()
}
```

- 前台收集必须用 `repeatOnLifecycle(STARTED)`，避免后台无谓触发
- 同一时刻只允许一轮 `runOnce`（`SyncEngine` 内 `Mutex`）

## 七、常见 bug 对照表

| # | 错误写法 | 正确做法 | 后果 |
|---|---|---|---|
| 1 | 用 Navigation Compose 做页面栈 | 自定义 `Screen` 状态导航 | 导航栈与投影状态不同步 |
| 2 | Composable 直接 collect Room `Flow` | 经 ViewModel 派生 `UiState` | UI 无法单测、依赖方向错误 |
| 3 | 切换工作区只换数据不重置 `search`/`activeTagId`/`Screen` | 统一 `resetWorkspaceScopedState()` | UI 显示旧筛选 |
| 4 | 先渲染种子数据再覆盖 | 启动占位到 `bootstrap` 完成 | 首屏闪变 |
| 5 | `BackHandler` 在所有屏幕都拦截 | 仅详情/历史/设置拦截，`Tasks` 交系统 | 无法退出 App |
| 6 | 同步状态直接在 Composable 里 `LaunchedEffect` 调用 `runOnce` | 由 `SyncNotifier` / 下拉刷新触发 | 重复触发、生命周期泄漏 |
| 7 | Worker 不用 `@HiltWorker` | `@HiltWorker` + `HiltWorkerFactory` | 依赖注入失败 |
| 8 | `SyncNotifier` 前台流不 `repeatOnLifecycle` | `repeatOnLifecycle(STARTED)` | 后台无谓同步 |
```

## 十二、Android 系统行为（minSdk 26）

| 项 | 要求 |
|---|---|
| 通知渠道 | 启动时创建 `reminder`、`sync`（API 26+ 必须） |

| 备份 | 排除令牌与 AI 密钥；`dataExtractionRules` 配合 |
